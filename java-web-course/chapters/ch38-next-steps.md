# 第 38 章　学完之后：后续学习路线

到这里，这本教程的正文就全部结束了。这一章不再是"学新知识"，而是帮你盘点一下"你现在手里有什么"，以及"接下来往哪个方向走"。

## 你现在已经具备的能力

如果你是从第 1 章一路做到第 37 章的最终项目，现在你应该已经能够独立完成这些事：

- 独立搭建一个 Spring Boot 项目，看懂 `pom.xml`、`application.yml`、`@SpringBootApplication` 分别在做什么。
- 设计一个符合 RESTful 规范的接口（资源式 URL + 标准 HTTP 方法），并用 `@RestController` 把它实现出来。
- 用 Controller-Service-Mapper 三层结构组织代码，说清楚每一层各自的职责边界。
- 用 MyBatis-Plus 完成单表甚至多表关联场景下的增删改查，包括基础分页。
- 用 DTO 把对外暴露的数据和数据库实体隔离开，用 `@Valid` 做参数校验，用 `@RestControllerAdvice` 做统一异常处理。
- 看懂并能画出"浏览器发请求到收到 JSON 响应"这条完整调用链，并且能对照任意一个 Spring Boot 项目的真实代码把这条链路讲清楚。
- 用 `@Transactional` 保证一组数据库操作的一致性。
- 给 Service 层和 Controller 层分别写最基础的自动化测试，理解单元测试和集成测试的区别。
- 面对一个报错（404/400/500/连接失败/Bean not found），有基本的排查思路，而不是完全懵。

这已经不是"玩具级别"的能力了——你现在能看懂、也能自己写出一个结构完整、能真实运行的后端项目雏形。

## 接下来可以深入的方向

本教程的定位是**零基础入门**，目标是让你从"完全不会"走到"能独立搭建一个结构完整的项目"。但企业级项目还有很多本教程刻意没有展开的内容，属于"学完这本教程之后"的进阶方向：

- **Spring Security / JWT 登录鉴权**：现在的 `task-manager` 项目里，任何人都能调用任意接口，没有"登录"和"权限"的概念。Spring Security 负责解决"谁能访问哪个接口"，JWT 是一种常见的"证明你已登录"的令牌方案。之所以现在不学，是因为它涉及过滤器链、认证/授权等一整套新概念，放在入门阶段会喧宾夺主。
- **Bean 生命周期扩展点**（`@PostConstruct`/`@PreDestroy`、`BeanPostProcessor` 等）：第 16 章讲 Bean 的时候特意降低了深度，只讲了"扫描 → 创建 → 注入 → 使用"这条主线。真实框架源码、中间件开发经常要用到生命周期扩展点做初始化/清理逻辑，属于往"框架原理"方向深挖的内容。
- **复杂分页性能优化**（COUNT 优化、深分页、游标分页）：第 37 章的分页只解决了"会用、看得懂返回结构"，数据量到百万级之后，`LIMIT` 分页会变慢，需要专门的优化手段，这属于数据库调优范畴，入门阶段不必纠结。
- **Redis 缓存**：真实项目里，频繁查询但不常变化的数据（比如用户信息）通常会缓存到 Redis 里，减少数据库压力。这需要先理解"缓存一致性"这个新问题（数据改了、缓存要不要跟着改），暂不涉及。
- **完整单元测试体系（Mockito / Testcontainers）**：第 37 章的测试例子里已经用到了一点点 `@MockitoBean`，但完整的 Mockito 用法（`when().thenReturn()`、参数匹配器、验证调用次数）以及 Testcontainers（测试时用容器启动一个真实的、临时的数据库）是更系统的测试工程能力，值得单独花时间学。
- **Docker 容器化部署**：现在项目是在你自己电脑上跑起来的，真实上线需要把项目和它依赖的环境（JDK、数据库等）打包成标准化的容器镜像，方便在任何服务器上一致地运行，这是运维/部署方向的入门知识。
- **CI/CD**（持续集成/持续部署）：代码提交后自动跑测试、自动构建、自动部署到服务器，是团队协作项目的标配流程，涉及 Git（第 34 章已经打了基础）之外的更多工具链知识。
- **微服务方向**：当一个项目大到一个团队管不过来时，会拆分成多个独立部署、通过网络互相调用的小服务（微服务）。这涉及服务注册发现、远程调用、分布式事务等一整套新问题，是"单体应用"学扎实之后才值得考虑的方向。

这些方向没有先后顺序的硬性要求，可以根据你实际遇到的需求（比如面试要求、工作任务）挑感兴趣的先深入。

## 结语

学完一门技术最好的方式不是收藏更多教程，而是拿一个能跑起来的项目，不断给它加功能、不断把它写"坏"再修好。建议你就用第 37 章的 `task-manager` 项目作为练手起点，试着自己加一些功能，比如：

- 给任务加一个"分类"（Category）概念，做一次新的多表关联练习；
- 给任务加一个"截止日期"（dueDate）字段，再做一个"查询即将过期任务"的接口；
- 做一次真正的多表关联查询——比如"查询某个用户的所有任务，同时把用户名一起返回"，体会一下比单表分页更复杂一点的查询场景怎么设计。

祝你在 Java Web 开发的路上越走越顺。
