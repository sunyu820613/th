# 阶段复习 1：Java 基础

## 知识地图

这一阶段（第 1～9 章）是整个教程的地基，按依赖顺序梳理一遍：

```
第1章 环境搭建
  └─▶ 第2章 变量、数据类型、运算符
        └─▶ 第3章 分支（if/else）与循环（for/while）
              └─▶ 第4章 数组 + 方法（参数/返回值/重载）
                    └─▶ 第5章 类与对象（字段/方法/构造方法/this）
                          └─▶ 第6章 封装(private+getter/setter)
                                     继承(extends)
                                     多态(重写@Override)
                                     接口(interface)
                                └─▶ 第7章 修饰符(public/private/protected/static/final)
                                            泛型(List<T> 编译期类型检查)
                                      └─▶ 第8章 集合(List/Map) + 枚举(enum) + 异常(throw/throws/try-catch-finally)
                                            └─▶ 第9章 Lambda + Stream + Optional + 注解入门
```

一句话概括每一环节在整体中的作用：

- **变量/分支/循环/数组/方法**：程序具备存数据、做判断、能重复、能封装小逻辑的基本能力。
- **类与对象**：把数据和操作数据的行为组织成一个整体，是面向对象的起点。
- **封装/继承/多态/接口**：让代码更安全（封装）、更少重复（继承）、更灵活可扩展（多态、接口）——这是后面理解 Spring "面向接口编程"的地基。
- **修饰符/泛型**：控制访问权限和归属（修饰符），把类型错误从运行时提前到编译时（泛型）。
- **集合/枚举/异常**：真实业务离不开的三大工具——存一批数据、表达有限选项、处理出错情况。
- **Lambda/Stream/Optional/注解**：更简洁的写法（Lambda、Stream），更明确的空值处理（Optional），以及理解"贴标签"这个心智模型（注解）——为下一阶段大量出现的 `@Xxx` 注解做铺垫。

## 易混概念对照

| 概念 A | 概念 B | 一句话区别 |
|---|---|---|
| `throw` | `throws` | `throw` 写在方法体内部，是**动作**——主动抛出一个具体的异常对象；`throws` 写在方法签名上，是**声明**——告诉调用者"这个方法可能会抛出某种异常"。 |
| 方法重载（Overload） | 方法重写（Override） | 重载发生在**同一个类**内部，方法名相同但参数列表（个数/类型/顺序）不同，编译期根据调用参数决定用哪个；重写发生在**父子类之间**，方法签名必须完全一致，子类重新实现父类的方法，运行期根据对象的实际类型决定执行哪个版本（多态的基础）。 |
| `List` | 数组（Array） | 数组长度创建后**固定不变**，用 `.length`（属性）取长度；`List` 长度可以随 `add`/`remove` **自动伸缩**，用 `.size()`（方法）取长度，并且 `List` 需要配合泛型（如 `List<User>`）在编译期做类型检查，而数组本身天然是强类型的（如 `int[]`、`User[]`）。 |
| `private` 字段 | `protected` 字段 | `private` 只能在**类自己内部**访问；`protected` 除了类自己，**子类**（即使在不同包）也能直接访问，是为继承关系专门留的"半开放"权限。 |
| `static` 成员 | 实例成员 | `static` 成员属于**类本身**，所有对象共享同一份，可以直接用"类名.成员名"访问；实例成员属于**每一个具体对象**，每个对象各有一份独立的数据，必须先创建对象才能访问。 |
| `Optional` | 直接判断 `== null` | 两者都能处理"值可能不存在"的情况，但 `Optional` 用类型把"这个值可能没有"这件事显式表达出来，更容易提醒开发者不要遗漏空值处理；`== null` 完全依赖开发者自己记得判断，容易遗漏。 |
| Lambda 表达式 | 匿名内部类 | 两者在效果上等价，都是"就地实现一个接口"；Lambda 只能用于**只有一个抽象方法的接口**（函数式接口），写法更简洁；匿名内部类没有这个限制，但写法更啰嗦。 |

## 测试题

1. 下面代码的输出是什么？
   ```java
   int score = 82;
   String grade;
   if (score >= 90) {
       grade = "优秀";
   } else if (score >= 75) {
       grade = "良好";
   } else {
       grade = "及格";
   }
   System.out.println(grade);
   ```

2. `for` 循环和 `while` 循环该如何选择？各举一个更适合的业务场景。

3. 下面代码会抛出什么异常？为什么？
   ```java
   int[] arr = new int[3];
   System.out.println(arr[3]);
   ```

4. 简述构造方法里为什么经常需要写 `this.name = name;` 而不是直接 `name = name;`。

5. 下面代码的输出是什么？说明理由。
   ```java
   Person p = new Student("小红", 20);
   p.introduce();
   // 假设 Student extends Person，并重写了 introduce()
   ```

6. `List<User> list = new ArrayList();`（右边没有加泛型参数）和 `List<User> list = new ArrayList<>();` 有什么区别？

7. 一个方法上写了 `@Override`，但实际上编译报错说"方法未覆盖或未实现父类型的方法"，最可能的原因是什么？

8. 用一句话解释"注解是什么"，并举一个到目前为止学过的注解例子。

<details>
<summary>参考答案</summary>

1. 输出 `良好`。因为 `82 >= 90` 不成立，跳到 `else if (score >= 75)`，`82 >= 75` 成立，赋值为 `"良好"` 并跳过后面的 `else`。

2. 循环次数或范围在写代码时就能确定（比如"遍历数组的每个元素""打印 1 到 100"）更适合用 `for`；循环次数依赖运行时才能知道的条件（比如"不断读取用户输入直到用户选择退出"）更适合用 `while`。

3. 抛出 `ArrayIndexOutOfBoundsException`（数组下标越界异常）。因为 `arr` 长度是 3，合法下标是 `0~2`，访问 `arr[3]` 超出范围。

4. 因为构造方法的参数名和字段名相同时，如果不加 `this.`，`name = name;` 会被理解成"参数自己赋值给自己"，字段根本没有被真正赋值；加上 `this.name` 明确表示左边是"当前对象自己的字段"。

5. 输出的是 `Student` 重写后 `introduce()` 里的内容。因为 Java 在运行时是根据变量**实际指向的对象类型**（这里是 `Student`）决定调用哪个版本的方法，即使变量声明的类型是父类 `Person`，这就是多态。

6. 右边没写 `<>` 里的类型参数（写成 `new ArrayList()`）是一种"原始类型"用法，编译器只会给出"未检查类型"的警告而不会报错，但会失去泛型在编译期的类型检查能力；写成 `new ArrayList<>()`（钻石语法）编译器会根据左边 `List<User>` 自动推断出这也是一个只能装 `User` 的 `ArrayList`，能获得完整的类型安全检查，是推荐写法。

7. 最可能是方法签名和父类（或接口）里的方法不完全一致——比如方法名拼写不同、参数类型或个数不同、参数顺序不同。`@Override` 的作用正是让编译器帮你检查这一点，如果没有真正构成重写，编译器就会在这里报错提醒你。

8. 注解是贴在代码（类、方法、字段等）上的一种"标签"，本身不会改变代码的执行逻辑，是否有实际效果取决于有没有工具或框架在特定时机读取这个标签并采取行动。例子：`@Override` 贴在方法上，编译器在编译阶段读取这个标签，检查这个方法是否真的构成了对父类或接口方法的重写。
</details>
