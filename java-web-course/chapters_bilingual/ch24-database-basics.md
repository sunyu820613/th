# 第 24 章　数据库基础概念 ／ 第24章　データベースの基礎概念

## 本章目标 ／ 本章の目標
理解数据库、表、行、列这几个最基础的概念；理解主键（Primary Key）的作用；对外键（Foreign Key）有一个初步的印象。

> 🇯🇵 データベース、テーブル、行、列といった最も基本的な概念を理解します。主キー（Primary Key）の役割を理解します。外部キー（Foreign Key）について初歩的なイメージを持ちます。

## 一句话理解 ／ 一言で理解する
数据库就是一个"专门用来长期保存数据、并且能被程序方便地查询和修改"的仓库，最常见的组织方式是"表格"——一张表就是一个 Excel 工作表那样的东西。

> 🇯🇵 データベース（Database、データを長期的に保存し、プログラムから簡単に検索・変更できる専用の倉庫）は、最も一般的には「表（テーブル）」という形で組織されます——1枚のテーブルはExcelのワークシートのようなものです。

## 为什么需要它 ／ なぜ必要なのか
到目前为止，我们写的 Project 2（内存版 User API）把用户数据存在一个 `List<User>` 里。这样做有个致命问题：**程序一重启，数据就没了**——因为内存里的数据只存在于程序运行期间。

> 🇯🇵 これまで作成してきたProject 2（メモリ版User API）では、ユーザーデータを `List<User>` に保存していました。この方法には致命的な問題があります。**プログラムを再起動すると、データが消えてしまう**のです——メモリ上のデータはプログラムの実行中しか存在しないからです。

如果想让数据"永久保存"，并且支持多个程序、多个人同时安全地读写，就需要一个专门的软件来做这件事——数据库（本教程用 **MySQL 8.x**）。数据库把数据整理成一张一张的"表"，这也是本章要学的内容。

> 🇯🇵 データを「永続的に保存」し、複数のプログラムや複数の人が同時に安全に読み書きできるようにするには、そのための専門ソフトウェアが必要です——それがデータベース（本チュートリアルでは **MySQL 8.x** を使用）です。データベースはデータを1枚1枚の「テーブル」として整理します。これが本章で学ぶ内容です。

## 核心概念 ／ コアコンセプト

### 24.1 表（Table）、行（Row）、列（Column） ／ 24.1 テーブル（Table）、行（Row）、列（Column）

一张表长得就像一个 Excel 表格：

> 🇯🇵 1枚のテーブルはExcelの表のような見た目をしています。

- **表（Table）**：一类数据的集合，比如"所有用户"就可以放在一张叫 `user` 的表里。<br><span class="ja-inline">🇯🇵 **テーブル（Table）**：ある種類のデータの集合です。例えば「すべてのユーザー」は `user` という名前のテーブルに入れることができます。</span>
- **列（Column）**：表里的"竖着的一栏"，代表这类数据的某一个属性，比如姓名、年龄。每一列都有固定的名字和固定的数据类型。<br><span class="ja-inline">🇯🇵 **列（Column）**：テーブル内の「縦の1列」で、このデータの特定の属性（名前、年齢など）を表します。各列には決まった名前と決まったデータ型があります。</span>
- **行（Row）**：表里的"横着的一条记录"，代表一条具体的数据，比如某一个具体用户。<br><span class="ja-inline">🇯🇵 **行（Row）**：テーブル内の「横の1件のレコード」で、具体的な1件のデータ（ある特定のユーザーなど）を表します。</span>

拿一张 `user` 表举例，它有 `id`、`name`、`email`、`age` 四列：

> 🇯🇵 `user` テーブルを例にすると、`id`、`name`、`email`、`age` の4つの列があります。

| id | name | email | age |
|---|---|---|---|
| 1 | 张三 | zhangsan@example.com | 25 |
| 2 | 李四 | lisi@example.com | 30 |
| 3 | 王五 | wangwu@example.com | 22 |

- 这张表叫 `user`。<br><span class="ja-inline">🇯🇵 このテーブルは `user` という名前です。</span>
- `id`、`name`、`email`、`age` 是它的 4 个列。<br><span class="ja-inline">🇯🇵 `id`、`name`、`email`、`age` はこのテーブルの4つの列です。</span>
- "1，张三，zhangsan@example.com，25" 是其中一行，代表用户张三这一条具体记录。<br><span class="ja-inline">🇯🇵 「1、张三、zhangsan@example.com、25」はその中の1行で、ユーザー张三というこの具体的なレコードを表します。</span>

### 24.2 主键（Primary Key） ／ 24.2 主キー（Primary Key）

观察上面的表，`id` 列有个特殊之处：每一行的 `id` 都不一样，而且一旦确定就不会再变。这样的列适合用来做**主键**——数据库里"唯一标识一行数据"的列。

> 🇯🇵 上のテーブルをよく見ると、`id` 列には特殊な点があります。各行の `id` はすべて異なり、一度決まると変わりません。このような列は**主キー（Primary Key、データベースで「1行のデータを一意に識別する」列）**にするのに適しています。

主键有两个硬性要求：

1. **唯一**：表里不能有两行的主键值相同。
2. **不能为空**：每一行必须有一个主键值。

> 🇯🇵 主キーには2つの厳格な要件があります。<br>1. **一意であること**：テーブル内に主キーの値が同じ行が2つあってはいけません。<br>2. **NULLにできないこと**：すべての行に主キーの値が必要です。

`user` 表里我们把 `id` 定为主键，意味着"只要给我一个 `id`，我就能唯一确定是哪个用户"，这比用 `name` 去找一个人靠谱得多——现实中同名同姓太常见了，而 `id` 保证不会重复。

> 🇯🇵 `user` テーブルでは `id` を主キーに定めます。これは「`id` を1つ渡してもらえれば、どのユーザーかを一意に特定できる」ということを意味し、`name` で人を探すよりもずっと信頼できます——現実には同姓同名が非常によくありますが、`id` は重複しないことが保証されています。

在建表的 SQL 里，主键通常这样声明（`AUTO_INCREMENT` 表示这一列的值由数据库自动生成，每插入一行自动加 1，不用你手动指定）：

> 🇯🇵 テーブル作成のSQLでは、主キーは通常次のように宣言します（`AUTO_INCREMENT` はこの列の値がデータベースによって自動生成され、行を挿入するたびに自動で1ずつ増えることを表し、自分で指定する必要はありません）。

```sql
CREATE TABLE user (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) NOT NULL,
    age INT
);
```

### 24.3 外键（Foreign Key）——先混个脸熟 ／ 24.3 外部キー（Foreign Key）——まずは顔なじみになろう

真实项目里，数据往往不是孤立的一张表，而是"表和表之间有关联"。举个例子：本教程最终项目（第 37 章的 Task 管理系统）里，除了 `user` 表，还会有一张 `task`（任务）表，每个任务都属于某一个用户。这时 `task` 表里会有一列 `user_id`，专门存"这个任务属于哪个用户的 `id`"：

> 🇯🇵 実際のプロジェクトでは、データは孤立した1枚のテーブルであることは少なく、「テーブル同士に関連がある」ことがほとんどです。例えば、本チュートリアルの最終プロジェクト（第37章のタスク管理システム）では、`user` テーブルのほかに `task`（タスク）テーブルもあり、各タスクは特定の1人のユーザーに属します。このとき `task` テーブルには `user_id` という列があり、「このタスクがどのユーザーの `id` に属するか」を専用に保存します。

| id | title | user_id |
|---|---|---|
| 1 | 完成周报 | 1 |
| 2 | 修复 Bug | 1 |
| 3 | 写测试用例 | 2 |

`task.user_id` 里的值，实际上就是 `user.id` 的值。像这种"一张表里的某一列，指向另一张表的主键"的设计，就叫**外键（Foreign Key）**。它的作用是让数据库能"知道"这两张表之间的对应关系，防止出现"任务的 `user_id` 指向一个根本不存在的用户"这种脏数据。

> 🇯🇵 `task.user_id` の値は、実際には `user.id` の値です。このように「あるテーブルの1つの列が、別のテーブルの主キーを指す」設計を**外部キー（Foreign Key）**と呼びます。その役割は、データベースがこの2つのテーブル間の対応関係を「把握」できるようにし、「タスクの `user_id` がまったく存在しないユーザーを指している」といった不正なデータが発生するのを防ぐことです。

外键涉及的多表关联查询（比如"查出张三的所有任务"要把两张表联合起来查）本章不展开，后面用到时再讲。这里你只需要记住一句话：**外键就是一张表里存了另一张表主键的值，用来表示"谁属于谁"这种关系**。

> 🇯🇵 外部キーが関わる複数テーブルの結合クエリ（例えば「张三のすべてのタスクを調べる」には2枚のテーブルを結合してクエリする必要がある）は本章では扱わず、後で使う際に説明します。ここでは次の一言だけ覚えておいてください。**外部キーとは、あるテーブルに別のテーブルの主キーの値が保存されており、「誰が誰に属するか」という関係を表すものです**。

## 最小示例 ／ 最小限のサンプル

用 SQL 建一张最基础的 `user` 表（下一章会详细讲 SQL 语句的具体用法，这里先感受一下"建表"长什么样）：

> 🇯🇵 SQLで最も基本的な `user` テーブルを作成します（SQL文の具体的な使い方は次章で詳しく説明します。ここではまず「テーブル作成」がどのようなものか体感してみましょう）。

```sql
CREATE TABLE user (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) NOT NULL,
    age INT
);

INSERT INTO user (name, email, age) VALUES ('张三', 'zhangsan@example.com', 25);
INSERT INTO user (name, email, age) VALUES ('李四', 'lisi@example.com', 30);
INSERT INTO user (name, email, age) VALUES ('王五', 'wangwu@example.com', 22);
```

## 代码逐行解释 ／ コードの行ごとの解説

- `CREATE TABLE user (...)`：创建一张名为 `user` 的表，括号里定义它有哪些列。<br><span class="ja-inline">🇯🇵 `CREATE TABLE user (...)`：`user` という名前のテーブルを作成し、括弧の中でどんな列があるかを定義します。</span>
- `id INT PRIMARY KEY AUTO_INCREMENT`：`id` 列，类型是整数（`INT`），`PRIMARY KEY` 声明它是主键，`AUTO_INCREMENT` 表示插入新行时不用手动指定 `id`，数据库自动从 1 开始往上加。<br><span class="ja-inline">🇯🇵 `id INT PRIMARY KEY AUTO_INCREMENT`：`id` 列は整数型（`INT`）で、`PRIMARY KEY` はこれが主キーであることを宣言し、`AUTO_INCREMENT` は新しい行を挿入する際に `id` を手動で指定する必要がなく、データベースが1から自動的に増やしていくことを意味します。</span>
- `name VARCHAR(50) NOT NULL`：`name` 列，类型是"最多 50 个字符的字符串"（`VARCHAR(50)`），`NOT NULL` 表示这一列不允许为空——建表时就规定"每个用户必须有名字"。<br><span class="ja-inline">🇯🇵 `name VARCHAR(50) NOT NULL`：`name` 列は「最大50文字の文字列」（`VARCHAR(50)`）型で、`NOT NULL` はこの列がNULLを許さないことを意味します——テーブル作成の時点で「すべてのユーザーは名前を持たなければならない」と規定しています。</span>
- `email VARCHAR(100) NOT NULL`：邮箱列，同理不能为空。<br><span class="ja-inline">🇯🇵 `email VARCHAR(100) NOT NULL`：メールアドレスの列で、同様にNULLにはできません。</span>
- `age INT`：年龄列，没写 `NOT NULL`，意味着允许这一列暂时不填（为空）。<br><span class="ja-inline">🇯🇵 `age INT`：年齢の列で、`NOT NULL` が書かれていないため、この列は一時的に未入力（NULL）にすることが許されています。</span>
- `INSERT INTO user (...) VALUES (...)`：往 `user` 表里插入一行数据。注意没有传 `id`，因为它是 `AUTO_INCREMENT`，数据库会自动生成 1、2、3。<br><span class="ja-inline">🇯🇵 `INSERT INTO user (...) VALUES (...)`：`user` テーブルに1行のデータを挿入します。`id` を渡していないことに注目してください。`AUTO_INCREMENT` なので、データベースが自動的に1、2、3を生成します。</span>

## 程序运行过程 ／ プログラムの実行の流れ

1. 执行 `CREATE TABLE` 语句，MySQL 在数据库里创建一张空的 `user` 表（0 行数据，但列的结构已经定好）。<br><span class="ja-inline">🇯🇵 `CREATE TABLE` 文を実行すると、MySQLはデータベース内に空の `user` テーブルを作成します（データは0行ですが、列の構造はすでに決まっています）。</span>
2. 依次执行 3 条 `INSERT` 语句，MySQL 每次往表里追加一行，`id` 自动生成为 1、2、3。<br><span class="ja-inline">🇯🇵 3つの `INSERT` 文を順番に実行すると、MySQLはそのたびにテーブルに1行を追加し、`id` は自動的に1、2、3と生成されます。</span>
3. 此时这张表就有了本章开头展示的那 3 行数据，之后可以被任何连接了这个数据库的程序查询到——哪怕程序重启，数据依然还在（这就是数据库和"内存 List"的本质区别）。<br><span class="ja-inline">🇯🇵 この時点で、このテーブルには本章冒頭で示した3行のデータが入り、以降はこのデータベースに接続したどのプログラムからでも検索できます——たとえプログラムを再起動しても、データは残ったままです（これがデータベースと「メモリ上のList」の本質的な違いです）。</span>
