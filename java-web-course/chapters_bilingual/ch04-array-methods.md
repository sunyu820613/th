# 第 4 章　数组与方法基础 ／ 第4章　配列とメソッドの基礎

## 本章目标 ／ 本章の目標
理解数组是什么、怎么声明和遍历，认识数组下标越界这个最常见的坑；理解方法的参数、返回值，以及"方法重载"的概念。

> 🇯🇵 配列とは何か、どう宣言し巡回するかを理解し、配列の添字（インデックス）が範囲外になるという最もよくある落とし穴を知ります。メソッドの引数・戻り値、および「メソッドオーバーロード（Overload、多重定義）」の概念を理解します。

## 一句话理解 ／ 一言で理解する
数组是"一排连续编号的盒子，每个盒子存同一种类型的数据"；方法是"把一段可能被反复用到的代码打包起来，起个名字，需要的时候直接叫它干活"。

> 🇯🇵 配列とは「連続して番号が振られた箱の列で、各箱には同じ種類のデータが1つ入る」ものです。メソッドとは「何度も使われる可能性のあるコードをひとまとめにして名前を付け、必要な時に呼び出して仕事をさせる」ものです。

## 为什么需要它 ／ なぜ必要なのか
如果要存 100 个学生的分数，总不能声明 100 个变量 `score1, score2, ..., score100` 吧？数组解决了"批量存储同类型数据"的问题。而如果计算"两个数之和"这段逻辑在程序里要用 10 次，每次都重新写一遍既麻烦又容易出错，方法解决了"把逻辑封装、复用"的问题。

> 🇯🇵 もし100人分の学生の点数を保存したいなら、まさか `score1, score2, ..., score100` のように100個の変数を宣言するわけにはいきません。配列は「同じ種類のデータをまとめて保存する」という問題を解決します。また、「2つの数の合計を求める」というロジックをプログラム内で10回使うとして、毎回書き直すのは面倒でミスも起きやすいものです。メソッドは「ロジックをカプセル化（封装）して再利用する」という問題を解決します。

## 核心概念 ／ コアコンセプト

### 4.1 数组的声明与初始化 ／ 配列の宣言と初期化

```java
int[] scores = new int[5];          // 声明一个能存 5 个 int 的数组，默认值都是 0
int[] ages = {18, 20, 22, 19};      // 声明的同时直接赋值，长度由数据个数决定（这里是 4）
```

- 数组一旦创建，**长度固定，不能再变**（想要"可变长度"的容器，后面第 8 章会学到 `List`）。<br><span class="ja-inline">🇯🇵 配列は一度作成すると**長さが固定され、変更できません**（「可変長」のコンテナが必要な場合は、後の第8章で学ぶ `List` を使います）。</span>
- 数组里的每个位置叫一个"元素"，用**下标（索引）**访问，**下标从 0 开始**，最后一个元素的下标是"长度 - 1"。<br><span class="ja-inline">🇯🇵 配列内の各位置は「要素」と呼ばれ、**添字（インデックス）**でアクセスします。**添字は0から始まり**、最後の要素の添字は「長さ - 1」になります。</span>
- 用 `数组名.length`（注意没有括号，这是属性不是方法）获取数组长度。<br><span class="ja-inline">🇯🇵 `配列名.length`（括弧が付かない点に注意。これはメソッドではなく属性です）で配列の長さを取得します。</span>

```
下标：   0    1    2    3
数组：[ 18,  20,  22,  19 ]
长度是 4，合法下标范围是 0~3
```

### 4.2 遍历数组 ／ 配列の巡回

最常见的写法是用 `for` 循环配合下标：

> 🇯🇵 最も一般的な書き方は、`for` ループと添字を組み合わせるものです。

```java
for (int i = 0; i < ages.length; i++) {
    System.out.println(ages[i]);
}
```

Java 还提供一种"增强 for 循环"（也叫 for-each），当你只关心"每个元素的值"、不关心下标时更简洁：

> 🇯🇵 Javaには「拡張for文」（for-eachとも呼ばれる）もあり、「各要素の値」だけに関心があり添字は気にしない場合、より簡潔に書けます。

```java
for (int age : ages) {
    System.out.println(age);
}
```

### 4.3 数组下标越界——最常见的坑 ／ 配列の添字が範囲外になる——最もよくある落とし穴

数组的合法下标是 `0` 到 `length - 1`。访问超出这个范围的下标（比如访问一个长度为 4 的数组的第 4 个元素 `ages[4]`，或者访问 `ages[-1]`），程序不会给你一个"空值"，而是会直接抛出异常并终止：

> 🇯🇵 配列の有効な添字は `0` から `length - 1` までです。この範囲を超えた添字にアクセスすると（例えば長さ4の配列の5番目の要素 `ages[4]` や `ages[-1]` にアクセスする場合）、プログラムは「空の値」を返すのではなく、直接例外をスローしてプログラムを終了させます。

```
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 4 out of bounds for length 4
```

这是初学者最容易踩的坑，尤其是在写 `for` 循环时把条件写成 `i <= ages.length`（多了一个等号）。

> 🇯🇵 これは初心者が最も踏みやすい落とし穴で、特に `for` ループの条件を `i <= ages.length`（等号が1つ多い）と書いてしまう場合によく起こります。

### 4.4 方法的参数与返回值 ／ メソッドの引数と戻り値

方法的基本结构：

> 🇯🇵 メソッドの基本構造：

```java
修饰符 返回值类型 方法名(参数类型 参数名, ...) {
    // 方法体
    return 返回值; // 如果返回值类型是 void，可以不写 return，或者只写 return; 提前结束
}
```

- **参数**：调用方法时传进去的数据，方法内部用参数名直接使用。<br><span class="ja-inline">🇯🇵 **引数（パラメータ）**：メソッドを呼び出すときに渡すデータで、メソッド内部では引数名でそのまま使います。</span>
- **返回值**：方法执行完之后"交还"给调用者的结果，类型必须和方法声明的返回值类型一致；如果方法不需要返回任何东西，返回值类型写 `void`。<br><span class="ja-inline">🇯🇵 **戻り値**：メソッドの実行が終わった後に呼び出し元に「返す」結果です。型はメソッド宣言時の戻り値の型と一致させる必要があります。何も返す必要がない場合は、戻り値の型を `void` とします。</span>

```java
public static int add(int a, int b) {
    return a + b;
}
```

调用时：`int result = add(3, 5);`——`3` 和 `5` 分别传给参数 `a` 和 `b`，方法执行完把 `8` 返回，赋值给 `result`。

> 🇯🇵 呼び出す時：`int result = add(3, 5);`——`3` と `5` がそれぞれ引数 `a` と `b` に渡され、メソッドの実行が終わると `8` が返され、`result` に代入されます。

### 4.5 方法重载（Overload） ／ メソッドオーバーロード（Overload）

**方法重载**指的是：**在同一个类中，可以定义多个同名方法，只要它们的参数列表不同（参数个数不同，或参数类型不同，或参数顺序不同）**，编译器会根据你调用时传入的参数自动匹配到对应的那一个。

> 🇯🇵 **メソッドオーバーロード（方法重载、多重定義）**とは、**同じクラス内に同じ名前のメソッドを複数定義できるという仕組みで、引数リストが異なりさえすれば（引数の個数が違う、型が違う、または順序が違う）**、コンパイラは呼び出し時に渡された引数に基づいて対応するメソッドを自動的に選び出します。

注意：方法重载和返回值类型无关，也和参数名无关——只看参数列表（个数、类型、顺序）。这一点在第 6 章会和"方法重写（Override）"放在一起对比，二者名字很像但完全是两回事。

> 🇯🇵 注意：メソッドオーバーロードは戻り値の型とは無関係であり、引数名とも無関係です——見るのは引数リスト（個数、型、順序）だけです。この点は第6章で「メソッドオーバーライド（Override、上書き）」と対比しますが、名前は似ていても全く別のものです。

```java
public static int add(int a, int b) {
    return a + b;
}

public static double add(double a, double b) {
    return a + b;
}

public static int add(int a, int b, int c) {
    return a + b + c;
}
```

上面三个方法名字都叫 `add`，但参数列表各不相同，这就是重载：调用 `add(1, 2)` 会匹配第一个，`add(1.5, 2.5)` 匹配第二个，`add(1, 2, 3)` 匹配第三个。

> 🇯🇵 上の3つのメソッドはすべて `add` という名前ですが、引数リストがそれぞれ異なります。これがオーバーロードです。`add(1, 2)` を呼び出すと1つ目に、`add(1.5, 2.5)` は2つ目に、`add(1, 2, 3)` は3つ目にそれぞれマッチします。

## 最小示例 ／ 最小限のサンプル

`ArrayAndMethodDemo.java`
```java
public class ArrayAndMethodDemo {

    public static void main(String[] args) {
        int[] scores = {88, 92, 76, 60, 45};

        // 遍历数组，统计及格人数
        int passCount = 0;
        for (int i = 0; i < scores.length; i++) {
            if (isPass(scores[i])) {
                passCount++;
            }
        }
        System.out.println("及格人数：" + passCount);

        // 增强 for 循环，计算总分
        int total = 0;
        for (int score : scores) {
            total += score;
        }
        System.out.println("总分：" + total);

        // 方法重载示例
        System.out.println("两数之和：" + add(3, 5));
        System.out.println("三数之和：" + add(3, 5, 10));
        System.out.println("小数之和：" + add(1.5, 2.5));
    }

    // 判断是否及格，返回 boolean
    public static boolean isPass(int score) {
        return score >= 60;
    }

    // 重载：两个 int 相加
    public static int add(int a, int b) {
        return a + b;
    }

    // 重载：三个 int 相加
    public static int add(int a, int b, int c) {
        return a + b + c;
    }

    // 重载：两个 double 相加
    public static double add(double a, double b) {
        return a + b;
    }
}
```

## 代码逐行解释 ／ コードの行ごとの解説

- `int[] scores = {88, 92, 76, 60, 45};`：声明并初始化一个长度为 5 的数组。<br><span class="ja-inline">🇯🇵 `int[] scores = {88, 92, 76, 60, 45};`：長さ5の配列を宣言し初期化します。</span>
- `for (int i = 0; i < scores.length; i++)`：用下标遍历，条件是 `i < scores.length` 而**不是** `i <= scores.length`——这是防止越界的关键写法，务必记住用 `<`。<br><span class="ja-inline">🇯🇵 `for (int i = 0; i < scores.length; i++)`：添字で巡回します。条件は `i < scores.length` であり、**`i <= scores.length` ではありません**——これは範囲外アクセスを防ぐための重要な書き方で、必ず `<` を使うことを覚えておいてください。</span>
- `if (isPass(scores[i]))`：`scores[i]` 取出下标为 `i` 的元素，作为参数传给 `isPass` 方法。<br><span class="ja-inline">🇯🇵 `if (isPass(scores[i]))`：`scores[i]` は添字 `i` の要素を取り出し、引数として `isPass` メソッドに渡します。</span>
- `public static boolean isPass(int score)`：方法接收一个 `int` 参数，返回一个 `boolean`，方法体只有一行 `return score >= 60;`，直接把比较结果作为返回值。<br><span class="ja-inline">🇯🇵 `public static boolean isPass(int score)`：`int` 型の引数を1つ受け取り、`boolean` を返すメソッドです。メソッド本体は `return score >= 60;` の1行だけで、比較結果をそのまま戻り値にします。</span>
- `for (int score : scores)`：增强 for 循环，每一轮 `score` 依次等于数组中的每一个元素，这里不需要也不能用下标。<br><span class="ja-inline">🇯🇵 `for (int score : scores)`：拡張for文で、毎回 `score` が配列内の各要素に順に等しくなります。ここでは添字は必要なく、使うこともできません。</span>
- `add(3, 5)` / `add(3, 5, 10)` / `add(1.5, 2.5)`：三次调用分别匹配到三个不同的重载方法，编译器在**编译期**就已经根据参数类型和个数确定好具体调用哪一个，不是运行时才决定的。<br><span class="ja-inline">🇯🇵 `add(3, 5)` / `add(3, 5, 10)` / `add(1.5, 2.5)`：3回の呼び出しはそれぞれ3つの異なるオーバーロードメソッドにマッチします。コンパイラは**コンパイル時点**で引数の型と個数に基づいてどれを呼び出すかを既に確定しており、実行時に決まるわけではありません。</span>

## 程序运行过程 ／ プログラムの実行の流れ

1. JVM 从 `main` 方法开始执行，创建数组 `scores` 并在内存中依次存入 5 个整数。<br><span class="ja-inline">🇯🇵 JVMは `main` メソッドから実行を開始し、配列 `scores` を作成してメモリに5つの整数を順に保存します。</span>
2. 进入第一个 `for` 循环，`i` 从 0 到 4 依次取值，每轮调用 `isPass(scores[i])`：<br><span class="ja-inline">🇯🇵 最初の `for` ループに入り、`i` が0から4まで順に値を取り、毎回 `isPass(scores[i])` を呼び出します。</span>
   - 调用 `isPass` 时，JVM 会为这次调用单独准备一块"方法执行空间"，把 `scores[i]` 的值拷贝给参数 `score`。<br><span class="ja-inline">🇯🇵 `isPass` を呼び出すとき、JVMはこの呼び出し専用の「メソッド実行領域」を用意し、`scores[i]` の値を引数 `score` にコピーします。</span>
   - 方法执行完 `return score >= 60;` 后，把 `true` 或 `false` 交还给调用处，这块临时空间随之释放。<br><span class="ja-inline">🇯🇵 `return score >= 60;` の実行が終わると、`true` または `false` を呼び出し元に返し、この一時的な領域は解放されます。</span>
3. 根据每次调用的返回值，决定是否让 `passCount++`。<br><span class="ja-inline">🇯🇵 毎回の呼び出しの戻り値に基づいて、`passCount++` を行うかどうかを決めます。</span>
4. 第二个循环用增强 for 遍历数组求和。<br><span class="ja-inline">🇯🇵 2つ目のループは拡張for文で配列を巡回して合計を求めます。</span>
5. 最后三次调用 `add`，编译器已经在编译时根据参数确定好每次具体走哪个重载版本，运行时依次执行、打印结果。<br><span class="ja-inline">🇯🇵 最後の3回の `add` 呼び出しは、コンパイラがコンパイル時点で引数に基づいてどのオーバーロード版を実行するかを既に確定しており、実行時には順に実行され結果が出力されます。</span>

输出：
> 🇯🇵 出力：
```
及格人数：4
总分：361
两数之和：8
三数之和：18
小数之和：4.0
```

## 常见错误 ／ よくあるエラー

| 现象 ／ 現象 | 原因 ／ 原因 | 解决 ／ 解決方法 |
|---|---|---|
| `ArrayIndexOutOfBoundsException` | 循环条件写成 `i <= scores.length`，或者手动访问了不存在的下标<br><span class="ja-inline">🇯🇵 ループ条件を `i <= scores.length` と書いてしまった、または存在しない添字を手動でアクセスした </span>| 遍历时始终用 `i < 数组.length`；牢记合法下标是 `0` 到 `length - 1`<br><span class="ja-inline">🇯🇵 巡回する際は常に `i < 配列.length` を使う。有効な添字は `0` から `length - 1` までであることを覚えておく </span>|
| `NullPointerException`（空指针异常） | 数组声明了但还没赋值就直接使用，比如 `int[] arr; System.out.println(arr[0]);`<br><span class="ja-inline">🇯🇵 配列を宣言したが値を割り当てる前に直接使用した、例えば `int[] arr; System.out.println(arr[0]);` </span>| 数组用之前必须先 `new` 出来或者直接赋初始值<br><span class="ja-inline">🇯🇵 配列を使う前に必ず `new` するか、直接初期値を代入する </span>|
| 编译报错，说找不到匹配的方法 `add(int, int, double)` | 调用方法时传入的参数类型和个数，没有任何一个重载版本能匹配<br><span class="ja-inline">🇯🇵 メソッド呼び出し時の引数の型と個数に、どのオーバーロード版もマッチしない </span>| 检查已定义的重载版本，确认参数个数和类型是否对得上，必要时新增一个重载<br><span class="ja-inline">🇯🇵 定義済みのオーバーロード版を確認し、引数の個数と型が合っているか確かめ、必要ならオーバーロードを追加する </span>|
| 两个重载方法参数列表实际上"看起来不同、其实相同" | 比如把 `add(int a, int b)` 和 `add(int x, int y)` 当成是两个不同的重载，实际上参数名不算数，这两个签名完全一样，会直接编译报错"方法重复定义"<br><span class="ja-inline">🇯🇵 例えば `add(int a, int b)` と `add(int x, int y)` を別々のオーバーロードだと思ってしまうが、実際には引数名はカウントされず、この2つのシグネチャは完全に同じであるため、コンパイル時に「メソッドが重複定義されている」というエラーになる </span>| 记住重载只看参数的**类型、个数、顺序**，参数名无关紧要<br><span class="ja-inline">🇯🇵 オーバーロードは引数の**型・個数・順序**だけを見ることを覚えておく。引数名は関係ない </span>|

1. 一个长度为 10 的数组，合法下标范围是多少？<br><span class="ja-inline">🇯🇵 長さ10の配列の有効な添字の範囲はどこからどこまでですか？</span>
2. 方法重载看的是方法的哪几个方面？返回值类型算不算？<br><span class="ja-inline">🇯🇵 メソッドオーバーロードはメソッドのどの側面を見ますか？戻り値の型は含まれますか？</span>
3. 下面代码有什么问题？<br><span class="ja-inline">🇯🇵 次のコードにはどんな問題がありますか？</span>
   ```java
   int[] arr = new int[3];
   for (int i = 0; i <= arr.length; i++) {
       System.out.println(arr[i]);
   }
   ```

<details>
<summary>参考答案 ／ 解答</summary>

1. `0` 到 `9`（长度为 10，下标从 0 开始，最后一个是 `length - 1 = 9`）。<br><span class="ja-inline">🇯🇵 `0` から `9` までです（長さが10で、添字は0から始まり、最後は `length - 1 = 9` になります）。</span>
2. 看方法名 + 参数列表（参数的类型、个数、顺序）。返回值类型**不算**——两个方法如果参数列表完全相同，仅返回值类型不同，是不允许的，编译会报错。<br><span class="ja-inline">🇯🇵 メソッド名 + 引数リスト（引数の型・個数・順序）を見ます。戻り値の型は**含まれません**——2つのメソッドの引数リストが完全に同じで戻り値の型だけが異なる場合は許されず、コンパイルエラーになります。</span>
3. 循环条件写成了 `i <= arr.length`，当 `i` 等于 `3`（也就是 `arr.length`）时，会尝试访问 `arr[3]`，但合法下标只到 `2`，会抛出 `ArrayIndexOutOfBoundsException`。正确写法是 `i < arr.length`。<br><span class="ja-inline">🇯🇵 ループ条件が `i <= arr.length` になっており、`i` が `3`（つまり `arr.length`）のとき `arr[3]` にアクセスしようとしますが、有効な添字は `2` までなので `ArrayIndexOutOfBoundsException` がスローされます。正しい書き方は `i < arr.length` です。</span>
</details>
